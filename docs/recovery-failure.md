# 自动恢复失败后的断开与通知

2026-10-10：自动恢复达到 3 次网络重试上限后，不再只记录日志并留下本地监听。

## 日志含义

- `heartbeat / socket_io`：认证 WebSocket 的底层连接发生 I/O 错误。
- `entry_handshake / connect`：已经解析到远程入口，但请求 NAS 登录页时连接失败，尚未进入加密登录及密码校验。
- 没有 HTTP 状态码意味着没有收到可用于分类的 HTTP 状态响应。当前安全诊断没有记录底层错误正文，因此不能据此进一步确定为 DNS、TLS、连接被重置或中继不可达中的哪一种。
- 重试耗尽后继续出现 `requestSessionUnavailable`，是旧逻辑仍保留本地 HTTP 监听；它会对新请求检查缺失的会话并记录警告。恢复失败锁存本来已阻止新一轮密码提交，警告数量不等于新增登录次数。

## 终态行为

1. 3 次可重试的网络失败后返回专门的 `recovery.exhausted`，保留原始错误类型和阶段用于安全诊断。
2. 持有连接操作锁，取消本连接心跳、域名同步与套餐读取任务。
3. 清除本连接 NAS 会话及内存自动恢复凭据，立即把 `connected` 标为 false，并移除旧认证方式、远程入口与套餐缓存。
4. 停止本连接全部本地监听；等待监听任务退出，必要时终止并等待任务取消，以释放端口。
5. 发送一次 `fn-proxy:connection-failed` 事件，前端展示错误提示并立即读取权威快照。
6. Rust 发送 Windows 系统通知；发送失败只记录脱敏警告，不恢复连接状态。
7. 保留失败锁存，不自动开始新一轮登录。显式手动连接才能重新配置恢复协调器。

认证拒绝、二次验证或协议错误等不可重试的自动恢复失败也进入上述终态，但提示不会宣称已经尝试 3 次。手动取消或断开不发送失败通知，旧恢复任务不能关闭随后建立的新会话。

清理仅针对失败的连接，不停止其他连接，不删除服务配置，也不删除 Windows 凭据管理器中用户保存的密码。

## 系统通知

使用 Tauri 官方通知插件的 Rust API，不向 WebView 开放发送通知的新增权限。文案与界面共用中英文本地化资源，语言由现有托盘文案同步路径传入后端。

Windows 正式应用身份通知需要使用安装版测试；开发模式可能显示 PowerShell 的名称和图标。系统通知设置、免打扰模式等可能影响弹出，因此同时保留应用内提示及日志。官方参考：Tauri v2 的 Notification 插件文档。

## 回归测试

覆盖网络尝试次数、专门的耗尽错误、超时和取消、20 个并发恢复请求只清理一次、停止监听后端口可重新绑定、会话及内存凭据清空、其他连接监听保留、失败锁存、中英文通知插值、前端失败事件的状态刷新，以及组件卸载后事件清理。
