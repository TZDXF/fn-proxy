# 当前账号完整端口 / 子域名发现调查

调查日期：2026-10-06。范围：用户 NAS 的公开 Web 前端、公开 FN Connect 入口与飞牛开发者文档。只读取公开静态资源；本轮没有获取真实密码、读取浏览器 Cookie、探测未知端口或修改 NAS 配置。

## 结论与覆盖边界

可以从经过 NAS 正常认证的 WebSocket RPC `appcgi.sac.entry.v1.getEntryList` 获取**当前登录账号可见的已注册入口**，然后读取入口中的 `uri.port` 与 `uri.fnDomain` 配对。公开桌面前端用同一个列表建立应用入口集合。

但以下集合不能混为一谈：

1. NAS 上实际监听的全部 TCP/UDP 端口。
2. 已被 FN Connect 注册/发布的 HTTP 服务入口。
3. 当前账号有权看到的入口。
4. 此刻通过中继实际可达的入口。

目前确认的是第 3 类中的端口 / 子域名配对；第 4 类需要逐个请求验证。没有确认一个可返回第 1 类全部端口及其 FN Connect 域名的全局 API，也没有证明未注册端口一定有对应域名。公开前端里没有找到某接口，不代表服务端内部一定不存在该接口。

“读取全部”在本应用中指读取本次 `getEntryList` 响应的所有条目，而不是承诺突破权限、枚举系统全部监听端口或得到其他账号私有入口。

## 已确认的读取流程

```text
正常 NAS 登录
  -> 建立带会话签名的 WebSocket RPC
  -> getEntryList，data.language = zh_CN
  -> 遍历 data.list（当前网页调用未提供分页参数）
  -> 每个入口保留 entryKey、title、uri.port、uri.fnDomain、uri.path
  -> 有有效 port + fnDomain：列为已注册映射候选
  -> 缺少字段：仍保留条目，说明不能建立端口代理的原因
  -> 只对已知映射进行显式服务测试，不扫描未知端口
```

远程地址由 NAS 返回的前缀拼接：

```text
https://{uri.fnDomain}.{NAS 主域名}{uri.path}
```

不能把 `uri.port` 直接当成中继 URL 的端口；客户端访问的是 HTTPS 443，NAS 端口来自服务端配置。域名哈希前缀及数字后缀仍未确认可计算，不能据此枚举其他端口。

本应用的代理上游配置使用服务域名根地址；原有 API 路径由本地请求保持。入口路径单独显示，剔除查询参数和片段，不因入口具有路径就丢失端口配对。

## Docker 或其他未列出端口怎么办

先从完整清单判断属于哪种情况：

- 有端口和有效 `fnDomain`：可以添加代理，随后测试实际 HTTP 响应。
- 有端口但没有 `fnDomain`：没有取得远程域名，不能猜测或自行补一个域名。
- 没有独立端口：可能是 NAS 内置应用、主站下的路径入口或其他入口类型；本阶段独立端口代理不处理这类入口。
- 完全没有该服务条目：需在 NAS 应用/Docker 的入口设置、应用用户权限及是否发布到 FN Connect 上进一步核对；不能据此断言服务没有监听。

开发者文档中的 manifest 字段 `service_port` 描述应用服务端口，`desktop_uidir` / `desktop_applaunchname` 描述桌面集成。它们不等价于“取得远程服务子域名”。具体服务如何注册、账号是否可见、fnOS 当前版本是否支持该入口，还需要 NAS 配置或实际返回值证据。

本轮不会自动修改入口、安装应用或扫描 1–65535 端口。若确需列出 NAS 所有监听端口，应在 NAS 本机采用经过授权的系统/容器管理方式盘点，再与当前账号入口列表交叉对照；这个盘点也不能为缺少映射的端口凭空产生远程域名。

## 本轮应用改动

新增桌面命令 `get_service_inventory`，仍只调用已确认的 `getEntryList`。返回：

- `totalEntries`：本次响应条目总数。
- `mappedEntries`：拥有安全有效端口与子域名配对的条目数。
- `unmappedEntries`：不能建立独立端口代理的条目数。
- `services`：按端口与远程根地址去重的可配置服务。
- `entries`：不去重的完整可见入口和未映射原因。
- `scope`：权限与覆盖范围提示。

前端“服务映射”页新增完整入口清单，包括无端口、缺少远程子域名、不安全域名及已注册待测试状态。格式错误的响应不会静默当作空列表。切换登录或断开时清除旧账号清单，结果只保留在应用内存中。

服务测试仍然只针对用户选择的已知域名发出 GET，不自动扫描。HTTP 401 可能是目标应用自身认证要求；403 也可能来自 FN Connect 或目标应用，仅凭状态码无法判定是哪一层拒绝。登记成功不代表业务 API 已经验证成功。
