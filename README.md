# FN Proxy

**让 NAS 服务通过本地地址访问。**

FN Proxy 是一款面向 Windows 的桌面应用，通过 FN Connect 登录飞牛 NAS，将已通过 FN Connect 暴露的 HTTP 服务映射到本机端口。浏览器、API 客户端和其他支持 HTTP 的工具可以使用本地地址访问远程服务，无需自行处理 FN Connect 的登录会话和服务凭据。

例如，将 NAS 上的服务映射到本机 `8084` 端口后，就可以通过 `http://127.0.0.1:8084/` 访问。

> FN Proxy 是独立工具，非飞牛官方客户端。它依赖 FN Connect 的现有服务入口，不是通用 VPN，也不提供任意端口穿透。

## 适合哪些场景

- **在本机访问远程 NAS 应用**：使用固定的本地地址打开 NAS 上的 Web 服务。
- **让 API 工具接入 NAS 服务**：将客户端的 Base URL 设置为本地地址，由 FN Proxy 处理 FN Connect 入口认证。
- **统一管理多个 NAS 或账号**：分别管理连接、服务映射和代理状态。
- **在可信局域网共享访问入口**：按需允许同一局域网内的其他设备通过运行 FN Proxy 的电脑访问服务。

## 主要功能

| 功能       | 说明                                                                                    |
| ---------- | --------------------------------------------------------------------------------------- |
| 多连接管理 | 保存多个 NAS / 账号，各连接独立维护会话、服务映射和代理，互不影响。                     |
| 服务发现   | 读取 NAS 桌面入口、Docker 快捷访问映射与容器端口信息，选择可用服务建立映射。            |
| 手动映射   | 自行填写服务的远程根地址、NAS 端口和本地端口。Docker 服务使用 NAS 宿主机发布端口。      |
| 本地代理   | 支持 HTTP、流式上传与下载、SSE 和 WebSocket，保留目标应用自身的认证方式。               |
| 域名同步   | 按 NAS 端口识别已映射服务；远程注册信息完整且匹配唯一时更新远程地址，保持本地端口不变。 |
| 会话维护   | 维持连接并更新服务凭据；连接丢失时尝试自动重新登录，失败或需要新验证码时需人工处理。    |
| 后台运行   | 关闭主窗口后继续在系统托盘运行，已建立的连接和代理不会因隐藏窗口而停止。                |
| 界面设置   | 支持简体中文 / English，以及亮色、暗色和跟随系统主题，自动保存偏好。                    |

## 使用前准备

- 一台运行 FN Proxy 的 Windows 电脑。
- 已启用 FN Connect、可通过 FN ID 访问的飞牛 NAS，以及具有相应服务权限的账号。
- 需要访问的服务已在 FN Connect 中提供可用的远程入口。仅有 NAS 端口或 Docker 端口并不足以建立映射。
- 如果账号启用了两步验证，准备当前验证码；首次绑定需先在 NAS 网页完成。

## 快速上手

### 1. 添加并连接 NAS

在 **连接** 页点击 **新增连接**，填写：

- **FN ID**：不带 `.fnos.net` 后缀。
- **用户名与密码**：NAS 的登录凭据。
- **两步验证码**：账号启用两步验证时填写。

点击 **保存连接** 只保存配置，不会立即登录。在连接列表点击 **连接** 发起登录，也可以在表单中点击 **测试连接** 验证配置。

可按需选择 **保存密码**。密码保存在 Windows 凭据管理器中，不写入应用配置文件；未保存密码时，再次连接需要输入密码。

### 2. 添加服务映射

在 **服务映射** 页选择对应连接，点击 **新增服务**：

- **服务发现**：点击 **读取服务**，选择可用服务并保存。
- **手动添加**：填写远程根地址、NAS 端口和本地端口并保存。

本地端口默认使用 NAS 服务端口，也可以改为其他端口。不同映射不能使用同一个本地端口；如果端口被其他程序占用，需要另选端口。

服务发现只允许选择已明确关联远程域名的 TCP 发布端口。无法匹配、存在歧义、UDP 或仅在容器内暴露的端口不会自动生成映射。

### 3. 开启代理并访问

在 **首页** 点击对应连接的 **开启代理**，然后使用服务映射中的本地地址访问。

假设服务映射到本地 `8084` 端口：

| 访问方式            | 地址示例                         |
| ------------------- | -------------------------------- |
| 浏览器              | `http://127.0.0.1:8084/`         |
| API 客户端 Base URL | `http://127.0.0.1:8084`          |
| WebSocket           | `ws://127.0.0.1:8084/实际WS路径` |

请求继续使用目标应用原本的 API 路径、方法、查询参数和请求体。如果应用要求 API Key、`Authorization` 或单独登录，仍需按该应用的规则提供；FN Proxy 只处理 FN Connect 入口认证，不替代目标应用的权限校验。

### 4. 管理运行中的服务

- 在首页查看连接状态、服务数量和代理运行情况，在 **运行日志** 页查看诊断信息。
- 代理运行时可以新增、编辑、删除服务或修改启用状态，保存成功后自动应用，无需先停止代理。
- 编辑同一本地端口的映射会更新后续请求的转发配置；变更端口、新增或启用服务会增量启动监听，删除或停用服务会释放对应端口，其他服务和连接不受影响。
- 端口冲突或配置保存失败时，保留原配置和运行中的监听；删除或停用最后一个服务后，该连接的代理变为已停止。
- 停止代理、断开连接或退出应用后，对应本地入口不再可用。

## 后台运行

点击窗口关闭按钮或按 `Alt+F4` 只会隐藏主窗口，应用仍在系统托盘运行。

- 单击托盘图标，或右键选择 **打开主窗口**，可恢复窗口。
- 需要完全退出时，右键托盘图标选择 **退出 FN Proxy**，应用会停止所有连接与代理并释放监听端口。
- 找不到托盘图标时，可以检查 Windows 托盘的隐藏图标区域。

## 局域网访问

默认情况下，代理只监听 `127.0.0.1`，仅本机可以访问。

如需让同一局域网的其他设备使用，在 **设置** 中开启 **允许局域网访问**。此设置适用于所有连接，修改前需停止全部代理，重新启动后生效。

开启后，其他设备可通过 `http://运行FNProxy的电脑局域网IPv4地址:映射端口/` 访问，例如 `http://192.168.1.10:8084/`。若无法连接，请检查系统防火墙是否允许对应端口；应用不会自动修改防火墙规则。

> 局域网入口没有额外的访问密码，访问者会共用当前 NAS 会话的服务访问凭据。仅在可信网络开启，不要将这些端口映射到公网。

## 运行日志文件

运行日志会自动追加到应用日志目录，Windows 下为
`%LOCALAPPDATA%\net.fnproxy.desktop\logs\fn-proxy.log`。关闭窗口隐藏到托盘时仍会继续记录，
重新启动应用也不会清空正常大小的日志文件。

- **大小限制**：每个文件最多 **5 MiB**；写入下一条日志会超限时，先轮转再写入。
- **备份保留**：保留 `fn-proxy.log.1`、`.2`、`.3` 三个备份，`.1` 最新，最旧备份自动删除；
  当前文件与备份合计最多 **20 MiB**。
- **格式**：UTF-8，每行一个 JSON 对象，包含毫秒时间戳、级别、连接标签及语言无关的消息代码和参数。
  可通过 `src/locales/zh-CN.json` / `en-US.json` 的 `backend` 翻译表查询消息含义。
- **界面日志**：仍只显示本次运行最近 200 条记录，历史记录请查看日志文件。
- **异常处理**：目录不可写或磁盘写入失败时，界面显示警告，连接与代理继续运行；
  初始化失败需修复目录权限后重启，运行中的写入失败会在后续日志到来时重试。
  单条日志超过 5 MiB 时不写入文件；启动时发现已有文件超过上限，会清空该文件以恢复大小限制。

文件仅记录已有运行日志事件及应用启停事件，不额外记录密码、Token、Cookie、请求头或请求体。
日志包含 FN ID 和连接标识，分享前请按需脱敏。

## 安全与限制

- **仅支持 HTTP 服务**：支持 HTTP / SSE / WebSocket，不转发 SSH、SMB、原生 TCP 或 UDP。
- **不会绕过认证**：两步验证、首次绑定、验证码以及目标应用自己的登录或 API 认证仍需正常完成。
- **本地入口需谨慎使用**：默认监听本机，但没有额外的本地访问密码，不适合在不可信的多人共用电脑上访问敏感服务。
- **服务兼容性有边界**：不改写网页或脚本中硬编码的远程绝对地址。依赖原始域名的 OAuth 回调、CORS 或绝对 URL 的应用可能需要额外配置。
- **浏览器 Cookie 可能冲突**：不同本地端口共享 `127.0.0.1` 的 Cookie 域，不同应用的同名 Cookie 可能互相影响。
- **远程域名不会被猜测**：服务注册信息不完整、无法匹配或存在多个候选地址时，会保留旧地址并记录警告，需要人工确认。
- **服务端会话由 NAS 管理**：删除本机保存的密码或断开连接，不等于撤销服务端已经签发的 Token。
- **依赖非官方接口**：认证实现基于公开前端代码分析，不是官方稳定 API；NAS 或 FN Connect 更新可能影响兼容性。

## 常见问题

**保存连接后为什么没有连上 NAS？**

保存配置和发起连接是两个独立操作。保存后需要点击 **连接**；未保存密码时需先输入密码。

**为什么发现了容器端口，却不能添加服务？**

容器端口不一定有 FN Connect 远程入口。只有明确关联可用远程域名的 TCP 发布端口才能用于映射。

**为什么关闭窗口后本地地址仍然可用？**

关闭窗口只会隐藏到系统托盘。要停止访问，可停止对应代理，或在托盘菜单中选择 **退出 FN Proxy**。

**为什么代理启动失败？**

先检查 NAS 是否已连接、本地端口是否被占用，再查看 **运行日志**。必要时更换本地端口，并确认服务具备有效的 FN Connect 入口。
